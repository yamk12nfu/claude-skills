# Skill Freshness — スキル鮮度チェックと対処提案

インストール済みスキルは静的ファイルで自動更新されない。出所台帳(`sources.json`)を使って配布元と照合し、**チェック→差分確認→対処提案→(承認後)実行**まで行う。チェック結果を並べるだけで終わらせず、必ず提案までやること。

## フロー

```
1. チェック実行      python3 scripts/check.py
2. 差分の中身確認    ⬆️ の項目を --diff で確認(全部でなく判断に必要な分だけ)
3. 対処提案          分類ルールに従い優先度付きの提案表を提示 ← ここまでが標準の成果物
4. 実行              ユーザーが承認した項目のみ。完了後に再チェックで✅確認
```

## 1. チェック実行

```bash
python3 ~/.claude/skills/skill-freshness/scripts/check.py           # 通常
python3 ~/.claude/skills/skill-freshness/scripts/check.py --offline # ネットワーク不可時
```

レポートは `last-report.md` にも保存される。状態: ✅=一致 / ⬆️=差分あり / ⚠️=照合失敗 / 未登録=出所不明。

## 2. 差分の中身確認

```bash
python3 ~/.claude/skills/skill-freshness/scripts/check.py --diff <skill-name>
```

- 出力は「ローカル→上流」方向。**`+`行 = 上流の新規内容 = 更新で取り込まれるもの**。
- 差分が巨大なスキルは全文を読まず、ファイル名一覧と主要ファイル(SKILL.md)の差分だけで判断する。
- **ローカル改変の有無の推定**: `ls -lT ~/.claude/skills/<name>/` で全ファイルのmtimeがインストール時期のまま揃っていれば、ユーザーは編集していない=差分は純粋な上流更新。mtimeがバラけていればローカル改変の可能性があるので保留系に倒す。

## 3. 対処提案(このスキルの本体)

各項目を以下のルールで分類し、提案表として提示する:

| 対象 | 条件 | 提案 | 優先度 |
|---|---|---|---|
| プラグイン | バージョン遅れ・内容差分 | 更新(公式配布物でローカル改変の前提がないため基本更新) | 高 |
| 上流追跡スキル | SKILL.md本文・scripts等の実質更新+ローカル編集痕なし | 更新 | 中〜高 |
| 上流追跡スキル | LICENSE.txt・体裁・PDF等の非本質差分のみ | 更新任意(まとめて更新 or 放置どちらでも) | 低 |
| 上流追跡スキル | ローカル編集痕あり | 保留。改変を残すか上流に合わせるかユーザーに確認 | 保留 |
| 上流追跡スキル | 上流でパス消滅・リポジトリ移動 | 出所再調査 or local扱いに変更 | 中 |
| 自作スキル | 60日超経過 | 点検候補: モデル名・CLI仕様・参照ツールの陳腐化がないか(勝手に書き換えない) | 低〜中 |
| 出所不明 | — | ①出所特定して台帳登録 ②使っていないなら削除 ③手元運用でよければ `type: local` に変更、の三択を提示 | 中 |

提案表の形式(実行コマンドをそのまま貼れる形にする):

```
| 対象 | 状態 | 提案 | 根拠 | 実行コマンド |
```

提案の際の注意:
- 差分の中身に**破壊的変更**(前提ツールの変更、構成の作り直し、動作フローの変更)を見つけたら根拠欄に明記する。
- ユーザーの利用実態が分かる場合(よく使うスキルか)は優先度に反映する。
- 提案を出したら**ユーザーの承認を待つ**。承認前に更新・削除を実行しない。

## 4. 実行(承認された項目のみ)

- **プラグイン**: `claude plugin update <name>@<marketplace>`
- **github-dir スキル**:
  ```bash
  rsync -a --delete ~/.cache/skill-freshness/<owner>__<repo>/<path>/ ~/.claude/skills/<name>/
  ```
- **github-file スキル**: raw URL から SKILL.md を取得して置き換え(frontmatter のローカル追記は保持する)
- **削除**: `rm -rf` の前に対象ディレクトリの中身を必ず確認
- 完了後 `check.py` を再実行し、対象が ✅ になったことを確認して報告する

## 新しいスキルをインストール・作成した時(重要な運用ルール)

直後に `sources.json` の `skills` へ出所を追記する。怠るとそのスキルは「未登録」になり鮮度チェック不能。

```jsonc
"<skill-name>": { "type": "github-dir",  "repo": "<owner>/<repo>", "path": "<repo内パス>" }  // ディレクトリごと導入(推奨)
"<skill-name>": { "type": "github-file", "repo": "<owner>/<repo>", "path": "<SKILL.mdパス>" } // SKILL.md単体導入
"<skill-name>": { "type": "local",   "note": "自作。<管理場所>" }
"<skill-name>": { "type": "unknown", "candidate": "<推定出所>" }
```

補足:
- `~/.agents/skills`(skills.sh CLI管理)と プラグインは自動でチェック対象になるため追記不要。
- 自作スキルを見直したら frontmatter に `last-verified: YYYY-MM-DD` を記録する。

# Artifact Format 判定スキル

成果物を作る前に、Markdown・HTML・両方のどれが適切かを判定して出力する。

## 役割の整理（最重要）

MDとHTMLは**役割が違う**。重複ではなく分担。

- **Markdown** = AI（Claude/subagent）と人間の両方が読む。**実装入力としての正本**。git管理。
- **HTML** = 人間専用。**視覚的な理解補助**（図・色・インタラクション）。配布・共有用。

この役割分担に従うと、3パターンに分かれる：

| パターン | 構成 | 主なケース |
|---|---|---|
| **MDのみ** | 正本だけで足りる | 視覚補助が不要・短い・git管理ドキュメント |
| **HTMLのみ** | 正本がいらない使い捨て | 共有レポート・編集UI・プロトタイプ |
| **MD + HTML** | 正本(MD) + 視覚補助(HTML) | 図示が必要なspec・要件定義+ステークホルダー共有 |

具体的なケース別の判定は後述の「判定例」表を参照。

## 大原則

1. **デフォルトはMarkdown**。HTMLや「両方」は根拠がある時のみ。
2. **HTMLは生成コスト2〜4倍**でdiffが汚い。それを上回るメリットが必要。
3. **「両方作る」場合は MD が正本、HTML は派生物**。詳細は後述の「MD+HTML 両方作る場合のルール」を参照。

## 判断フレームワーク（5軸）

各軸でMD寄りかHTML寄りか判定し、優勢な方を採用する。

| 軸 | Markdown寄り | HTML寄り |
|---|---|---|
| **寿命** | 長期保守・継続更新 | 一度きり・スナップショット・使い捨て |
| **読み手** | 自分・Claude（実装入力として再読込） | 他人・非エンジニア・経営層・レビュアー |
| **編集頻度** | Claude/手で頻繁に編集 | 一回作って終わり |
| **視覚要素** | テキスト・コード中心 | 図・色・テーブル・SVG・インタラクション必須 |
| **git追跡** | リポジトリにコミットする | コミットしない・配布物 |

## 判定アルゴリズム

```text
Step 1: 正本（AI/人間が読み戻す source of truth）が必要か？
  - 必要（実装入力・git管理・継続更新） → MDを作る（必須）。Step 2へ
  - 不要（共有・使い捨て・スナップショット） → Step 3へ

Step 2: MDだけで人間が十分理解できるか？
  - YES（テキスト中心・短い・図不要）
    → MDのみ で確定
  - NO（図示必須・配布対象に非エンジニアあり・複雑な構造の可視化が要る）
    → MD + HTML（視覚補助つき）で確定

Step 3: 正本不要の場合、HTMLにする価値があるか？
  3a. 視覚要素が必要 or 30行超 or インタラクション/編集UIが要る
      → HTMLのみ で確定
  3b. それ以外（短いSlack貼付サマリ・口頭共有メモ・3〜10行）
      → MDのみ（共有用に整形して出力）。HTML化はオーバーキル

Step 4: 判断が割れた時のみ、1問だけ確認:
  「これは実装に渡す/git管理しますか？それとも共有・配布用の使い捨てですか？」
```

## 実行手順

1. ユーザーの要求から成果物の性質を読み取る（正本が必要か／視覚補助が必要か）
2. アルゴリズムで「MDのみ／HTMLのみ／MD+HTML」を決定する
3. 判断が割れた時のみ1問確認する（即決できるなら聞かない）
4. 出力先パスを決める（後述「ファイル配置のデフォルト」）
5. 決定した形式で出力する
6. 出力時に**1行だけ理由を添える**:
   - MDのみ: 「→ Markdownで作成（理由: 実装specとしてClaudeが読み戻すため、図示不要）」
   - HTMLのみ: 「→ HTMLで作成（理由: 経営層共有用、使い捨て）」
   - 両方: 「→ MD（正本）+ HTML（視覚補助）で作成。HTMLは状態遷移図を含む」

## MD + HTML 両方作る場合のルール

両方を出力する時、以下を**全て**満たす。これが守られないと必ずどちらかが腐る。

1. **MDが正本（source of truth）**。HTMLは派生物。
2. **内容を二重に書かない**。MDの本文をHTMLにコピーしない。HTMLは図・色・インタラクションで補助する役割に徹する。
3. **HTML冒頭に正本リンクを明記**:
   ```html
   <p><strong>正本</strong>: <a href="./xxx.md">xxx.md</a>（このHTMLは視覚補助。仕様の真実はMDを参照）</p>
   ```
4. **MD更新時はHTMLを捨てて再生成**。差分同期しようとしない。
5. **ファイル名を揃える**: `feature-spec.md` + `feature-spec.html`（拡張子だけ違う形）
6. **同じディレクトリに並べて置く**。HTMLからMDへの相対リンクを必ず張る。

## ファイル配置のデフォルト

出力先パスは以下の方針で決める（ユーザーが明示しない場合）:

- **MDのみ・git管理対象**: プロジェクト直下の `docs/` または既存のドキュメントディレクトリに置く（既存の慣習に合わせる）
- **MDのみ・短いメモ**: ユーザーが明示する場所、なければ確認する
- **HTMLのみ・git管理しない**: プロジェクト内に置く場合は `.gitignore` に追加するか、`./scratch/`・`./tmp-html/`・`~/Downloads/` など明示的に追跡しない場所を選ぶ。**コミットしないHTMLをそのままリポジトリ直下に置かない**
- **MD+HTML 両方**: 同じディレクトリ。MDがgit管理ならHTMLも同じ場所に置いてgit管理（または`.gitignore`で除外する場合は明示）

## 出力時の注意

### Markdownを選んだ場合（単独 or 両方の正本として）
- 100行を超えそうなら見出し階層を整理し、目次を冒頭に置く
- ASCIIアートで色・複雑な図を頑張らない → 必要ならHTML併用に切り替える
- コードブロックには言語タグを付ける（` ```ts ` 等）
- 拡張子は `.md`
- 両方作る場合: 末尾または冒頭に「視覚補助: ./xxx.html」とリンクを置く

### HTMLを選んだ場合（単独 or 補助として）

#### 必須: 関連skillの併用

HTMLを生成する**前に**、以下を必ず参照する。これを怠るとgeneric AI HTML（淡いグラデ＋丸角カード＋無難サンセリフのテンプレ感）が生成される。

1. **`frontend-design` skill を必ず参照する**（任意ではなく必須）
   - 「テンプレ感のあるデフォルトに読めない、意図的で独自性のあるビジュアルデザイン」の指針を与えるskill
   - HTML artifact生成時のベース品質はこれで担保する
2. テーマ性を出したい時は **`theme-factory` skill** を併用（10種のプリセットor生成）
3. Anthropic ブランド準拠が要る時は **`brand-guidelines` skill** を併用

#### ファイル構成

- **単一HTMLファイル**にCSS/JSを埋め込む（外部依存なしでブラウザで開ける）
- 拡張子は `.html`、生成後 `open <path>` でローカルブラウザで開ける状態にする
- インタラクティブにする場合は「copy as JSON / copy as prompt」ボタンを付ける（Claude Codeに戻すため）

#### 最低品質ライン（これを満たさないHTMLは出さない）

frontend-design に任せるのが基本だが、それを呼ばずに直書きする場合でも以下は最低限満たす:

- **フォント**: `system-ui, -apple-system, "Segoe UI", "Helvetica Neue", sans-serif` などの system font stack を使う（Times New Roman放置はNG）
- **配色**: CSS Custom Properties で配色トークンを定義し、ハードコード色は本文中に書かない
  ```css
  :root {
    --bg: #ffffff;
    --fg: #1a1a1a;
    --muted: #6b7280;
    --accent: #2563eb;
    --border: #e5e7eb;
  }
  ```
- **ダークモード対応**: `@media (prefers-color-scheme: dark)` で配色トークンを上書きする
- **行間とmax-width**: 本文 `line-height: 1.6〜1.75`、コンテナ `max-width: 720〜880px` 中央寄せ。フル幅で書かない
- **見出しスケール**: h1〜h3 で明確な階層差を付ける（同じサイズに見えないこと）
- **コードブロック**: 等幅フォント・薄い背景・横スクロール可（`overflow-x: auto`）
- **レスポンシブ**: モバイル幅でも読める（`<meta name="viewport">` 必須、コンテナ幅は `max-width` で）

## アンチパターン

### 形式選択のアンチパターン
- ❌ MarkdownでASCII図・色を頑張って表現する → HTMLを併用すべき（または HTMLのみ）
- ❌ HTMLで実装spec/要件定義の本文を書いてsubagentに渡す → MDが正本、HTMLは補助に
- ❌ **同じ内容**をMarkdownとHTMLに二重に書く → HTMLは「図・色・インタラクション」だけに徹する
- ❌ git管理する設計ドキュメントの**本文**をHTMLで書く → 本文はMD
- ❌ 「とりあえず両方作っときます」（理由なく両方） → 役割分担の根拠がある時だけ両方にする
- ❌ 短い（〜30行）メモをHTMLで作る → 過剰
- ❌ 両方作るのにHTMLに「正本: xxx.md」を書き忘れる → どちらが真実か分からなくなる
- ❌ コミットしないHTMLをリポジトリ直下に置きっぱなし → `.gitignore` に追加するか別ディレクトリへ

### HTML品質のアンチパターン（generic AI HTML を避ける）
- ❌ `frontend-design` skill を呼ばずにHTMLを直書きする → 量産系の見た目になる
- ❌ デフォルトのbrowser stylesheetそのまま（Times New Roman・青下線リンク・フル幅本文）
- ❌ **何にでも淡いグラデーション** + **何にでも丸角カード** + **何にでもパステル**のテンプレ感
- ❌ セクション見出しに無闇な絵文字装飾（🚀✨🎉 で章を区切る等）→ 内容と無関係なら入れない
- ❌ ダークモード未対応で目が痛い真っ白背景固定（`prefers-color-scheme` を必ず実装）
- ❌ 配色をハードコード（`#fff` `#000` `blue` を本文中に直書き）→ CSS Custom Properties で集約
- ❌ コンテナ幅 `max-width` 未指定で本文が画面横いっぱいに伸びる → 行が長すぎて読めない
- ❌ アイコンを画像URLで取得（外部依存・404リスク）→ SVG をインラインで埋め込む
- ❌ JavaScript で外部CDN（jQuery, Tailwind CDN等）→ 単一ファイル原則を守る、必要ならインラインCSSで足りる

## 注意点

### PR説明用 explainer の現実解
GitHub の PR 説明欄は HTML をレンダリングしない。「PR添付用にHTML作って」と言われた時の現実的な対処:

- **PR本文はMarkdown**で書き、補助HTMLは別途生成して GitHub Pages / gist / S3 にホストし URL を貼る
- もしくは HTML をレンダリングしてスクリーンショットを撮り、PR本文に画像として貼る
- HTML をそのまま PR 本文にコピペしようとしない

## 判定例

| 要求 | 判定 | 理由 |
|---|---|---|
| 「この機能のspec書いて」（図不要） | MD のみ | 実装入力・git管理・テキストで足りる |
| 「複雑な状態遷移を含むspec書いて」 | **MD + HTML** | MD=正本、HTML=状態遷移図 |
| 「大規模リファクタの計画書作って」 | **MD + HTML** | MD=タスク詳細、HTML=影響範囲・依存関係図 |
| 「経営層にも共有する要件定義」 | **MD + HTML** | MD=エンジニア向け正本、HTML=非エンジニア向けサマリー |
| 「上司向けに四半期の成果まとめて」 | HTML のみ | 共有・使い捨て・正本不要 |
| 「アーキテクチャ図を含む解説」 | HTML のみ または MD+HTML | git管理するなら両方、共有だけならHTMLのみ |
| 「タスクの優先度を並び替えるUI欲しい」 | HTML のみ | 編集UI・使い捨て |
| 「TODOリスト作って」 | MD のみ | 短い・編集頻繁 |
| 「Slackに貼る短文サマリ作って」 | MD のみ | 短い・コピペで足りる・HTML化は過剰 |
| 「デザインの3案を比較したい」 | HTML のみ | 視覚比較・探索フェーズ |
| 「README更新して」 | MD のみ | git管理・規約 |
| 「PR説明用のexplainer作って」 | MD（PR本文）+ HTML（補助・別ホスト） | 「注意点」参照。HTML単独でPRに貼らない |
| 「次スプリントの計画書」 | MD のみ | git管理・編集頻繁・テキストで足りる |
| 「色のバリエーションを試したい」 | HTML のみ | 色表現必須・使い捨て |
| `CLAUDE.md` `AGENTS.md` の編集 | MD のみ | 規約・git管理 |
| 設計メモ・ADR・技術メモ | MD のみ | git管理・継続参照 |
| subagent駆動開発の `task_plan.md` 等 | MD のみ | AI読み戻し前提 |
